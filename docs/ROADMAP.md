## معايير القبول (قابلة للاختبار)

### المرحلة 1
1. `pytest` ناجح على Python 3.12 و 3.15.
2. التغطية ≥ العتبة (⚠️ SPEC؛ المقترح 80%) لطبقتي domain و application.
3. `<cli> --help` وكل أمر P1 يعملان بلا شبكة وبلا أي متغير بيئة لمفاتيح API (PRV-002).
4. إنشاء مشروع في مجلد مؤقت ينتج ملف YAML وسجل SQLite متوقعين، والعملية idempotent.
5. محاولة الكتابة خارج جذر المشروع تُرفض برمز خروج ≠ 0.
6. YAML غير صالح أو خبيث يُرفض برسالة واضحة (safe-load فقط).
7. تطبيقا Repository (SQLite و in-memory) يجتازان نفس مجموعة الاختبارات.
8. اختبار الحدود: domain و application لا يستوردان adapters.
9. تحديث TRACEABILITY: كل بنود P1 بحالة `Verified` مع معرفات الاختبارات.

### المرحلة 2
1. وكيل يُعرَّف من YAML بكل الخصائص الأصلية (⚠️ SPEC) ويُرفض التعريف غير الصالح.
2. سير عمل نموذجي يُنفَّذ بكل مراحله الأصلية (⚠️ SPEC) باستخدام test-double executor.
3. مقاطعة التنفيذ ثم استئنافه من آخر checkpoint ينتج نفس النتيجة.
4. خطوة تتطلب موافقة تتوقف حتى الموافقة أو الرفض، ويُحفظ القرار.
5. عملية خطرة بلا صلاحية تُمنع افتراضيًا (deny-by-default).
6. البوابة غير المهيأة تُسجَّل `not evaluated`.
7. Workflow لا يستورد router أو providers (boundary test).

### المرحلة 3
1. Mock Provider يجتاز مجموعة اختبارات العقد كاملة.
2. الـ Router يعطي اختيارات حتمية لجدول سيناريوهات يغطي كل معيار ومستوى أصلي.
3. لا يُختار نموذج محلي أو مجاني يفتقد قدرة مطلوبة (RTR-002).
4. كل استدعاء يُسجَّل في Cost؛ تجاوز الميزانية يطبق السياسة المهيأة.
5. السجل اليدوي بلا مصدر سعر أو تاريخ تحقق يُرفض.
6. تشغيل كامل بلا مزود حقيقي ناجح.

### المرحلة 4
1. الذاكرة تحفظ القرارات والسياق كملفات Markdown مقروءة ومفهرسة في SQLite، ويمكن استرجاعها.
2. إضافة ملف تعريف تقنية جديد لا تتطلب تغيير الكود.
3. كل ملف تعريف وقالب أصلي (⚠️ SPEC) موجود ويجتاز التحقق.
4. إنشاء مشروع من كل قالب في مجلد مؤقت.

### المرحلة 5
1. لكل إطار وأداة: سجل تحقق (رابط رسمي + تاريخ + الواجهة المستخدمة) قبل أي كود.
2. كل محول يعلن مستوى قدرته ويجتاز اختبارات العقد.
3. النظام يجتاز كل الاختبارات مع غياب أي أداة أو إطار (absence tests).
4. Antigravity: إما AGY-G1 مُجتازة أو `Deferred` موثق.

### المرحلة 6
1. فشل أي بوابة جودة يمنع القبول (integration test).
2. اختبارات أمنية: منع الأوامر والمسارات خارج السياسة؛ لا أسرار في السجلات؛ فحص أسرار للمستودع.
3. سيناريو تكامل شامل ناجح باستخدام Mock Provider.
4. تثبيت نظيف على Ubuntu 24.04 وفق الوثيقة، ثم تشغيل `<cli> --help` بنجاح.

### المرحلة 7: Final Audit
1. كل متطلب حالته `Verified` (تنفيذ + اختبار ناجح) أو `Deferred` بقرار موثق منك.
2. إعادة تحقق كل تكامل مع وثائقه الرسمية (تواريخ محدثة).
3. مراجعة أمنية ومراجعة اعتماديات (لا K8s/Kafka/Vector DB؛ Docker غير إلزامي).
4. تقرير نهائي: منجز / متبقٍ.
